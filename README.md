# AI советник для игры Аким на 5 часов

Это самостоятельная основа части Персоны 3 на Python 3.10+. Она объясняет меры,
предлагает наборы решений и готова принимать результаты будущего движка.
Сейчас движка расчёта Score нет. Каталог взят из предоставленного
«Датасет районов.docx». Эти данные описывают учебную модель города.

## Как работает советник

1. Пользователь задаёт вопрос: «Что такое M5?» или «Помоги соцсфере Нуры».
2. Код добавляет каталог, правила и выбранные решения в контекст модели.
3. Если включено suggest, модель предлагает до трёх наборов для проверки.
4. Код проверяет состав наборов. При подключённом движке вызывает его для каждого
   уникального допустимого варианта. Без движка возвращает unverified и никаких баллов.
5. Модель получает доступные факты и результаты проверок, затем пишет брифинг.
6. Код проверяет структуру ответа и существование ссылок на факты.
7. Игрок видит объяснение и варианты; решения автоматически не меняются.

Это ограниченный агентный процесс: модель выбирает варианты, программа вызывает
инструмент проверки, затем модель интерпретирует ответы. Здесь используется
структурированный план, а не нативный function calling провайдера. Без движка
доступны консультация и непроверенные предложения. Обучать новую модель не нужно.

## Запуск без API ключа

Из папки проекта:

```bash
python3 -m akim_ai --provider demo --input examples/request.json
python3 -m akim_ai --provider demo --input examples/plan.json
```

Режим demo выдаёт заранее написанный текст про M5 и пример набора из задания.
Он проверяет путь данных, не понимает произвольные вопросы и не является настоящим AI.
В ответе всегда видны provider=demo и предупреждение. Пакеты устанавливать не нужно.

## Установка как пакета

Для отдельного окружения и команды `akim-advisor`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
akim-advisor --provider demo --input examples/request.json
```

В Windows активация: `.venv\Scripts\activate`. Зависимостей времени выполнения нет.
Каталог включён в пакет: после установки библиотека и чат работают вне папки исходников.
Путь `--input` и `.env` отсчитываются от текущей папки; запрос также можно передать
через stdin: `akim-advisor --provider demo --input -`.
Режимы `--input`, `--chat` и `--check-config` взаимоисключающие.

## Настоящая модель

Есть сменный адаптер OpenAI Responses API. Выбор этого провайдера не обязателен:
для другого сервиса достаточно реализовать метод generate, описанный ниже.

Скопируйте .env.example в .env и заполните OPENAI_API_KEY и OPENAI_MODEL локально.
Существующий .env не перезаписывайте. Можно вместо файла задать переменные через
настройки IDE/терминала: окружение имеет приоритет над .env. Ключ не вставляйте в
исходники, Git или сообщения чата. Допустимы строки KEY=VALUE, кавычки вокруг значения
и отдельные строки комментариев. Shell-команды и подстановка переменных не выполняются.
Нужна доступная вашей учётной записи модель с поддержкой Responses и JSON Schema.

```bash
python3 -m akim_ai --provider openai --input examples/request.json
python3 -m akim_ai --provider openai --input examples/plan.json
python3 -m akim_ai --provider openai --check-config
```

--check-config проверяет только наличие настроек; он не вызывает API и не подтверждает
валидность ключа, баланс или доступность модели. --env-file позволяет указать другой файл.

В request.json изменяйте question. decisions может быть пустым или содержать текущий
неполный выбор. suggest=false отвечает на вопрос; suggest=true дополнительно запускает
планирование вариантов. Один запрос использует до двух обращений к модели.
Таймаут каждого обращения — 45 секунд. Автоматических повторов платных вызовов нет.

Адаптер построен по [официальной документации Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Внешний API при подготовке проекта не вызывался: ключ и конкретная модель не заданы.
Живые ответы и качество русских объяснений ещё нужно проверить с выбранной моделью.

## Чат с памятью

```bash
python3 -m akim_ai --provider openai --chat
```

Обычный вопрос запускает планировщик и объяснение. Если нужно только объяснить термин,
используйте /ask — так будет один запрос к модели. Пример диалога:

```text
/priority Школы и поликлиники Нуры
Предложи подходящий набор мер
А почему ты выбрал эти меры?
Замени M5 на другой вариант, если это допускают правила
/show
/choose candidate_1
/ask Что такое лаг?
/exit
```

Предложения и принятые игроком решения хранятся отдельно. /choose принимает один из
последних предложенных наборов; это не расчёт его последствий. /show показывает данные
каталога: стоимость, лаг, район. Арифметика стоимости выполняется кодом, а не моделью.
По-прежнему нельзя показывать вычисленный Score без движка.

Команды:

| Команда | Действие |
|---|---|
| /priority ТЕКСТ | Закрепить приоритет между запусками |
| /priority - | Удалить закреплённый приоритет |
| /choose candidate_1 | Принять конкретный предложенный набор |
| /show | Посмотреть приоритет, принятые решения и последние варианты |
| /ask ВОПРОС | Получить объяснение без генерации новых вариантов |
| /new | Очистить историю, приоритет и решения текущего диалога |
| /help | Показать команды |
| /exit | Сохранить и завершить чат |

Память хранится локально в .sessions/openai.json. Файл исключён из Git.
Сохраняются до 12 обменов сообщениями и до 24 000 символов истории; при превышении
ограничения удаляются старые пары сообщений. Закреплённый приоритет и принятые решения
хранятся отдельно и не исчезают при сокращении истории. Поэтому важные постоянные цели
закрепляйте через /priority. Обычные пожелания модель получает из последних сообщений.
При смене приоритета /priority заменяет прошлое значение.

Другой диалог запускается с --session .sessions/second.json. Используйте отдельный файл
для каждого одновременно работающего чата. Запись атомарная, с блокировкой и проверкой
версии: устаревший экземпляр не может затереть изменения другого чата. Если возник
конфликт, перезапустите чат для загрузки актуальной памяти. Ответ выводится до сохранения,
поэтому ошибка записи не скрывает полученное объяснение. Неизменённая память не
перезаписывается. Если процесс аварийно завершился во время записи и остался файл
`<имя-сессии>.lock`, убедитесь, что все использующие его чаты закрыты, и удалите этот lock.
При каждом вопросе контекст передаётся OpenAI; серверное хранение ответа отключено
параметром store=false. Это не утверждение о полном отсутствии служебного хранения у
провайдера. Подход к передаче контекста описан в
[официальной документации Conversation state](https://developers.openai.com/api/docs/guides/conversation-state).

Можно проверить команды без API:

```bash
python3 -m akim_ai --provider demo --chat
```

Демопамять хранится отдельно в .sessions/demo.json. Деморежим по-прежнему выдаёт
фиксированный пример, а не осмысленный ответ на произвольное продолжение разговора.

## Что получает интерфейс

- status: ok, invalid_input, invalid_simulation или unavailable.
- mode: consult до расчёта или analyze после передачи достоверного результата.
- briefing: summary, strengths, risks и next_step.
- simulation: исходный расчёт, скопированный без пересчёта, или null.
- candidates: полные наборы, гипотеза reason, статус, результат проверки.
- evidence: факты, на которые ссылаются текстовые утверждения.
- warnings: например, сообщение о недоступности объяснения.

Статусы вариантов: unverified — нет расчёта; invalid — нарушены правила;
error — проверка не удалась; verified — движок рассчитал вариант.
verified не означает, что вариант улучшает текущий балл. Пока сравнение дельт не
пришло от движка, интерфейс не должен показывать автоматически придуманное улучшение.
reason всегда остаётся исходной гипотезой модели.

Числа показывайте из simulation и candidates[].simulation. Инструкция модели запрещает
переписывать Score и дельты в текст. Проверка evidence_ids подтверждает существование
источника, но не доказывает смысловую точность текста — её оценивают на живых ответах.

## Файлы для твоей работы

- akim_ai/prompts.py — роль советника и правила его поведения.
- akim_ai/agent.py — последовательность планирования, проверок и объяснения.
- akim_ai/contracts.py — структура ответов и локальная проверка JSON.
- akim_ai/providers.py — настоящий API и отдельный фиксированный деморежим.
- akim_ai/session.py — память, приоритеты и принятие предложенного набора.
- akim_ai/chat.py — интерактивный чат в терминале.
- akim_ai/config.py — чтение локальной конфигурации без исполнения команд.
- akim_ai/catalog.json — меры, районы, показатели и правила из датасета.
- examples/ — запросы, которые можно менять без редактирования кода.
- tests/ — проверки управления процессом; синтетические баллы в тестах не являются
  результатами расчёта датасета.

## Что можно делать сейчас

Настрой модель и пробуй вопросы: «Что значит лаг?», «Объясни M5»,
«Почему нельзя M1 вместе с M3?», «Предложи меры для школ и поликлиник Нуры».
Для вопросов о терминах используй suggest=false. Для предложения наборов — true.
Проверь понятность языка, соответствие каталогу и явное указание отсутствия расчёта.

Это библиотека, CLI для одного запроса и чат в терминале с постоянной локальной
историей. Веб-интерфейс и HTTP endpoint можно добавить при интеграции с приложением.

## Подключение движка позже

Персона 1 пока не требуется. Когда функция будет готова:

```python
from akim_ai import Advisor
from akim_ai.providers import OpenAIModel

# server_simulate принимает {"decisions": [...]} и возвращает результат движка.
advisor = Advisor(OpenAIModel(), simulator=server_simulate)
current = server_simulate({"decisions": selected_decisions})
answer = advisor.run(
    "Объясни результат и предложи варианты",
    selected_decisions,
    suggest=True,
    simulation=current,
)
```

simulation передаёт только доверенный сервер после расчёта соответствующих решений.
Не принимайте готовые числа от браузера как достоверный результат.
Адаптер simulator должен иметь собственный сетевой таймаут, если он вызывает HTTP.
После объединения замените локальный каталог общим каталогом проекта и синхронизируйте
проверку правил. Она помогает отсеивать предложения, но движок остаётся решающей проверкой.

Для замены модели реализуйте generate(stage, instructions, payload, schema) -> dict.
stage равен plan или brief. Метод должен возвращать JSON-объект по schema или
выбрасывать исключение. Advisor обработает сбой и сохранит имеющийся расчёт.

## Проверки

```bash
python3 -m unittest discover -s tests -v
```

Проверяются отсутствие ложной верификации, ограничения числа вариантов, повторы,
некорректный ответ модели, неизвестные ссылки, сбои движка и сохранение результата
при сбое AI. Это проверки кода, а не оценка качества реальной языковой модели.
Дополнительно проверяются продолжение диалога, ограничение памяти, независимость сессий,
явное принятие мер, повреждённые файлы, конфигурация, формат API-запроса и ошибки доступа.
Регрессионные тесты проверяют конкурирующие записи, сбой атомарного сохранения,
некорректные ответы API, отказ модели, таймауты, ограничение размера JSON,
повторяющиеся JSON-поля, ввод через stdin и вывод результата движка в терминале.

При живой проверке последовательно спросите «Хочу помочь Нуре», «А если важнее школы?»,
«Замени одну меру», затем перезапустите чат и спросите «Какой у меня приоритет?».
Убедитесь, что ответы учитывают историю, а варианты не выдают непроверенные баллы.

## Оптимизация запросов

Варианты передаются модели один раз в `evidence.candidate_*`; дублирующее поле `checks`
удалено из внутреннего payload. Внешний ответ `Advisor.run` сохраняет поля `candidates`
и `evidence`. JSON в API-запросе сериализуется без лишних пробелов.
Для адаптеров моделей источником статусов вариантов теперь служит `evidence.candidate_*`.

Повторяемый локальный замер:

```bash
python3 -m tools.benchmark_payload
```

На фиксированном примере с одним вариантом объём JSON-контекста брифинга уменьшен
с 7716 до 6674 байт (13,50%). Это размер UTF-8 payload, не измерение токенов,
цены или задержки живого API. Содержимое каталога и результатов сохранено.
